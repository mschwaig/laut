# Build Evidence Fixtures

`aterm/<input-hash>` contains Sigstore v0.3 bundles as JSON
Lines, matching the runtime cache layout.

The 314 claims were migrated from commit `4ee196c`. Each original JWS signature
was verified with its corresponding checked-in builder test key before the
input/output claim was mapped to the SLSA profile and re-signed with Ed25519ph.
The input hashes, output paths, NAR hashes, and castore entry bytes were retained.
Invocation IDs are the first 16 bytes of SHA-256 of the original compact JWS,
encoded in lowercase hex, to make this fixture migration deterministic.

Debug preimages retain the resolved ATerm; obsolete JSON-preimage debug data
was removed. The tracked builderA lookup maps now contain decoded in-toto
statements. These are test claims, not evidence from newly executed builds.

## Sibling Identity Migration

The 314 DSSE claims in the 157 tracked collections were subsequently migrated
from the immutable source commit
`49feb5f79f4eb756765e8f600e41ee9e89ba104a`. A one-time Rust generator authenticated
each original signature over its exact DSSE payload bytes using Ed25519ph
(SHA-512 of DSSE PAE, empty context), independently of payload-profile validation.
It required exactly one matching checked-in builder key, the matching signed
builder ID, the original input hash matching the collection filename, and no
transparency-log entries. The corresponding private key re-signed the result;
both checked-in keypairs and the original bundle key hints were retained.

The input identity moved from `externalParameters.resolvedInputHash` to
`externalParameters.resolvedInput.digest.nix-resolved-derivation`. Each subject
still describes one logical output, with sibling `digest` entries:

- `nix-ca-store-path`: the original `annotations.laut_storePath`.
- `nix-nar-sha256`: the original `digest.sha256`, unchanged lowercase hex.
- `snix-castore-entry`: the original `annotations.laut_castoreEntry`, unchanged
  base64 of the structured castore reference, not a hash of NAR bytes.

The old identity fields and subject `mediaType: application/x-nix-nar` were
removed, not retained as compatibility aliases. Output names, output order,
`laut_output` metadata, supplementary annotations, debug contents, builder
versions, invocation IDs, and collection filenames were preserved. In
particular, absent `criticalFeatures` remains absent. Reversing just these field
moves recovered each complete original statement before re-signing. No builds
were rerun, and no stronger claim about output contents was introduced.

Generation used deterministic compact JSON payloads and JSON Lines bundles,
with a final newline, and prepared all replacements before writing. Destinations
had to be tracked and match either the source commit or the regenerated bytes.
Only the 157 collections and the two tracked builderA lookup maps were rewritten;
the maps contain authenticated transformed statements in their original
array-valued groups. Untracked builderB maps and `by_name` files are not part of
this corpus and were left untouched. The temporary generator was not retained.

## ATerm Scheme Migration

The 314 DSSE claims in the 157 tracked collections were migrated from the pinned
source commit `e977b9d1ee5e10388f86d89234884da909832475`. A temporary Rust example
run with `nix develop -c cargo run -p laut-sign --example migrate_aterm_fixtures`
authenticated every original bundle with `Bundle::verify` and the checked-in
builderA and builderB test keys. It required exactly one DSSE signature, exactly
one matching signer, no transparency-log entries, and a canonical input hash
matching the collection filename. Both private keys were checked against their
checked-in public keys.

Only `externalParameters.resolvedInput.digest.nix-resolved-derivation` was
renamed to `externalParameters.resolvedInput.digest.aterm`. The matching private
key re-signed each transformed statement using `Bundle::sign`; `Bundle::verify`
authenticated the new signature, and reversing the key rename recovered the
complete original statement. All other statement fields and bundle metadata
were preserved, including key hints, debug preimages, invocation IDs, and absent
fields. Only the DSSE payload and signature bytes changed within each bundle.
No builds were rerun and no hash values were recomputed.

Collections moved from `nix-resolved-derivation/` to `aterm/` without changing
filenames or claim order. Generation prepared all replacements before writing,
used deterministic compact JSON Lines with a final newline, and checked that
the source files matched the pinned commit. The two tracked builderA decoded
maps were regenerated from authenticated transformed statements, retaining
their group keys, array shape, order, and all other contents. A second generator
run with `--check` verified byte-for-byte deterministic regeneration. Existing
untracked builderB maps and `by_name/` files were checked unchanged. The temporary
generator was removed after verification.

The profile is documented in `docs/slsa-provenance-v1.md`. Integration tests use
these local fixtures and never query public infrastructure.

`consolidate.py` inspects bundle collections without signature verification.
Its groups are based on unauthenticated hints, not trusted signer identities.
The historical MinIO-internals extractor is only for old archived test data;
export new bundle objects through the storage service's normal object API.
